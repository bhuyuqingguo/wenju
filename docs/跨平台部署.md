# 打包规则

这份说明按文矩 3.3.0 写成，目录名和检查脚本可以直接搬到别的产品。产品名换成自己的，版本号和文件名必须一致。文矩这一版界面、启动器和关于页都写的是 3.3.0，所以包名是 `WenJu_3.3.0_...`。

## 目录

解压后的最外层只有两样东西：一个程序文件夹，一个入口文件。

- Windows：`打开文矩.exe` 和 `文矩/`。入口 exe 内嵌图标。它在当前用户的桌面和开始菜单建快捷方式，并尝试锁定到任务栏。不写 HKLM，不提权。
- Linux / 麒麟：`打开文矩.sh` 和 `文矩/`。脚本可执行。它把图标装到 `~/.local/share/icons/hicolor`，把 `.desktop` 装到 `~/.local/share/applications`，并用 `xdg-user-dir DESKTOP`（中文环境是「桌面」）再放一份。`gio set metadata::trusted true` 用来避免「不受信任」。
- 卸载：Windows 开始菜单里的「卸载文矩」，或 Linux `sh 打开文矩.sh --uninstall`。只删快捷方式和用户图标，不删程序文件夹。
- 任务栏：Windows 7 可以调用「锁定到任务栏」。Windows 10/11 经常拒绝程序自己固定，这时只保留桌面和开始菜单。GNOME / UKUI 能改 `favorite-apps` 就追加；KDE 没有稳定的免交互固定方式，只保证开始菜单。

## 图标

源文件是 `core/素材/文矩_图标.svg`。`launcher/make_icon.py` 生成 ico 和 hicolor。`launcher/check_icons.py` 在打包时运行，缺尺寸就失败。

- Windows 入口 exe 必须有 GROUP_ICON，至少 16、24、32、48、256。`python.exe` / `pythonw.exe` 仍是 CPython 的图标，不能当作入口。
- 窗口图标用同一张图：`setWindowIcon`。任务栏图标来自这个窗口图标。快捷方式的 `IconLocation` 指向带资源的 `文矩.exe`。
- `AppUserModelID` 固定为 `WenJu.Desktop.3.3`，和进程里 `SetCurrentProcessExplicitAppUserModelID` 一致。
- Linux：`StartupWMClass=wenju`。进程在创建 QApplication 之前调用 `setDesktopFileName('wenju')`，并把 argv[0] 设为 `wenju`，这样 `WM_CLASS` 的两段都是 `wenju`。hicolor 里要有同样的 16/24/32/48/256。程序文件夹放 `.DirIcon`。本产品不用 AppImage，也不做 deb；如果以后做 AppImage，根上还要有 `.DirIcon`。

## 字体

见 [字体.md](字体.md)。正文首选仿宋_GB2312，没有就用仿宋，docx 写实际选中的名字。商业字体不进包。可选文件放在程序旁的「可选字体」。Windows 7 不能注册用户字体，只在进程里加载。

## Windows 7 发版前

1. 在 Windows 7 SP1 x64 上安装 KB2670838 后再打开 Win7 包。干净的 SP1 没有 `d3d11.dll`，Qt 5.15 会直接加载它。
2. 双击最外层的 `打开文矩.exe`。确认资源管理器里这个 exe 不是 Python 图标，桌面快捷方式图标相同，窗口标题栏也是同一张图。
3. 跑 `launcher/pe_imports.py`，不能出现 `api-ms-win-core-path`、`CopyFile2`、`GetSystemTimePreciseAsFileTime`、`SetThreadDescription`。
4. 在没有仿宋_GB2312 的系统上整理一份 docx，样式里的 eastAsia 应是「仿宋」。两个都没有时，启动要出现字体说明。
5. 这台打包机没有可用的 Win7 安装镜像，也没有把当前用户加入 kvm 组。替代步骤在 `launcher/win7-vm.ps1`：在自己的 Windows 上用已有的 ISO 启动 Hyper-V 或 VirtualBox。

## 当前产品的包

- Windows 10/11 x64：Python 3.13 与 PySide6 6.10.3。不能在 Windows 7 上启动。
- Windows 7 SP1 x64：Python 3.8.10 与 PySide2 5.15.2.1。不要和上面的 runtime 混用。
- 银河麒麟 V10 ARM64 与 x86_64：Python 3.11 与 PySide6 6.8.3，glibc 符号不超过 2.17。用户入口是 `打开文矩.sh`，它再调用 `launcher/start-kylin.sh`。

## 当前状态
- Windows 10/11 x64：自带 Python / Qt 运行库，EXE manifest 为 asInvoker；普通用户解压运行，不安装服务、不写注册表。这个包不能在 Windows 7 上启动。
- Windows 7 SP1 x64：单独的便携包，Python 3.8.10 与 PySide2 5.15.2.1。构建见 `launcher/package_win7.py`，说明见 [Windows7兼容.md](Windows7兼容.md)。不替换上面的 Win10/11 包，也不替换麒麟包。
- 银河麒麟 V10：ARM64 与 x86_64 便携包各自带 Python 3.11 与 Qt/PySide6 6.8.3 运行库（符号版本不超过 glibc 2.17，可在 glibc 2.28 的麒麟 V10 上加载）。入口是 `sh launcher/start-kylin.sh`，诊断是 `sh launcher/diagnose-kylin.sh`。Windows runtime 不能用于 Linux。飞腾/鲲鹏真机上的图形与性能尚未在打包环境中测得。
- 数据：优先便携目录“工作数据”，不可写时回退当前用户 LocalAppData/WenJu 或 XDG_DATA_HOME/WenJu。不会要求管理员权限。
- 动效：分页只创建当前 9 张模板卡；悬停缩放、按钮按压、页面淡入，未使用模糊/粒子/视频。外观中可关闭动效。
- 兼容模式：Windows `文矩.exe --safe-render`；Linux `sh launcher/start-kylin.sh --safe-render`。软件渲染并关闭交互动效及开场；用于显卡驱动问题，不能保证比硬件加速更快。

## 麒麟打包前必须确定的运行基线
在普通用户终端运行 `sh launcher/diagnose-kylin.sh`，收集系统版本、架构、glibc、图形会话。诊断不修改系统。
Qt 官方说明：旧于预编译包构建环境的 glibc 可能需要从源码构建 Qt；Linux ARM 不能仅凭架构名称判断兼容。
参考：https://doc.qt.io/qt-6.10/supported-platforms.html
软件渲染说明：https://doc.qt.io/qt-6/qtquick-visualcanvas-adaptations.html

PySide6 6.10 的 Linux 预编译轮子要求 glibc 2.34（x86_64）或 2.39（ARM64），不能作为麒麟 V10 的运行库。已发布的麒麟包改用 conda-forge 上 glibc 2.17 基线的 Python 3.11、PySide6 6.8.3、Qt 6.8.3，并带上 xcb / Wayland 插件及其依赖库，放在 `runtime/bin/python3`。若以后改用更新的官方 wheel，需在最旧目标麒麟上从源码构建 Qt/PySide6，不在用户电脑上升级系统库。不得直接复制 Windows runtime，亦不得把 glibc 强塞入用户系统。
启动脚本保留相对路径，打包 tar.gz 保留可执行权限；不依赖 AppImage 的 FUSE 安装条件。部署过程中不使用 sudo/apt/rpm。

## 验收矩阵（待真机执行）
飞腾与鲲鹏各至少一台：8GB 内存、普通账户、离线、无管理员权限；X11/实际 Wayland 会话；硬件及软件渲染。
- 解压到带中文/空格路径，首次启动、再次启动、关闭动画、皮肤和大字切换。
- 115 套模板搜索、分类、分页、编辑、另存、导入导出。
- 红头机关/文号/签发人生成；无机关名称须提示；二次整理不重复插入自有红头。
- 100 页 DOCX 与批量任务期间界面可操作；记录首屏耗时、滚动帧时间、峰值 RSS、处理耗时。目标：常用交互帧时间 p95 不超过 33ms，空闲内存目标低于 350MB；目前并未测得麒麟指标。
- 只读程序目录回退用户目录、注销后再启动偏好仍在。
- 字体完整性：环境检测逐一查找。方正/GB2312 字体不能假定机器自带，也不能未经许可打包字体；使用单位已有字体或用户提供的合法字体文件。
- DOCX 不依赖 Office；旧 DOC/WPS/RTF 需要电脑已有可用转换组件，这部分不能承诺零依赖。
